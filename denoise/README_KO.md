# FPGA CNN 이미지 잡음 제거기

잡음 섞인 흑백 사진을 넣으면 FPGA가 깨끗한 사진을 돌려줍니다. CIFAR 분류에 썼던 **같은 비트스트림**
(K=1152, COUT=128, P=16, T=4, 런타임 형상)을 그대로 쓰고, 망만 분류용에서 잡음 제거용으로 바꿨습니다.

## 설정

표준 설정인 DnCNN(Zhang et al., 2017)과 같습니다.

| 항목 | 내용 |
|---|---|
| 학습 사진 | Train400 (BSD 180×180 흑백 400장) 중 380장, 20장은 검증용. 40×40 또는 50×50 패치, 4가지 크기 × 8가지 뒤집기/회전 |
| 테스트 사진 | Set12 (12장), BSD68 (68장) |
| 잡음 | 가우시안 백색 잡음 σ=25 (0~255 기준) |
| 학습 종료 | 검증 PSNR이 6 epoch 동안 안 오르면 학습률 반감, 15 epoch 동안 안 오르면 종료. 검증 최고 모델 사용 |

하드웨어 때문에 바꾼 것이 두 가지 있습니다. **비교 대상도 모두 이 조건에서 다시 측정했습니다.**

1. **잡음 사진을 [0,1]로 자르고 7비트로 양자화합니다.** 코어 입력 포트가 7비트 부호 없는 값이기 때문입니다.
2. **마지막 층이 깨끗한 사진을 직접 출력합니다.** DnCNN은 잡음을 예측해서 빼지만, 코어는 모든 출력에 ReLU를 걸기 때문에 음수가 있는 잡음은 낼 수 없습니다. 잡음 사진을 마지막 층에 한 채널 더 넣습니다(skip).

- **QAT의 효과:** 정수 손실(Set12 / BSD68)이 같은 예산판 시드 1 maxout 0.16 / 0.14 → 0.01 / 0.01, ReLU 0.05 / 0.02 → 정수가 float보다 0.04 / 0.02 높음, B 0.04 → 0.01 dB(조기 종료판 maxout 0.22 → 0.02). ReLU·maxout 시드 2·3과 45채널 망까지 PTQ 손실은 0.02–0.25 dB이고(평균 결합 시드 2는 0.29 / 0.17), QAT 뒤 ReLU·maxout·45채널 모델은 모두 0.04 dB 이내다. 평균 결합 시드 2의 QAT 모델은 표의 'float'(양자화를 끈 FoldedQ)이 BSD68 27.78로 정수 28.82보다 1 dB 낮은데, 양자화를 끄면 활성값 클리핑(0–127·a)까지 꺼지기 때문이다: BSD68 한 장이 8.74 dB로 무너지고, 클리핑만 남기면 평균 28.75 dB다. 보드가 계산하는 정수 값과는 상관없지만, 이 모델의 float 열은 비교 기준이 아니다. 이 QAT는 epoch 2가 검증 최고였다(정수 검증 28.251 → 28.392, float 28.436).
- **BM3D 조건:** 클리핑 7비트 입력은 BM3D에 BSD68 0.26 dB 손해를 준다(`bm3d_protocol.py`; 포화 픽셀이 많은 영상에 집중). σ를 학습 영상 40장에서 다시 골라도(σ=23) −0.06 / +0.09 dB로 0.1 dB 이내.
- **같은 입력의 DnCNN-S:** `dncnn_s_protocol.py`. 공개 가중치(float, 556k, 클리핑 없이 학습)가 30.35 / 28.89(클리핑 없는 입력 30.44 / 29.24로 문헌 재현). 화질 모델은 Set12 0.2 dB 낮고 BSD68 0.1 dB 높지만, 후자는 학습 분포 차이라 이득으로 세지 않는다.
- B-32 ReLU·maxout은 시드 세 개(학습 1·2·3, QAT 단계는 모두 3), 평균 결합은 두 개, 나머지는 하나다. 시드 하나인 망끼리의 0.1 dB 미만 차이는 해석하지 않는다.

### SSIM (`ssim_eval.py` → `ssim_eval.json`)

Wang et al. (2004)의 SSIM: 8비트 영상, 11×11 가우시안 창(σ 1.5), K1 0.01, K2 0.03, 범위 255, 영상 평균(`skimage.metrics.structural_similarity`, `gaussian_weights=True, use_sample_covariance=False`). 정수 모델은 보드 드라이버의 host 에뮬레이션(보드와 비트 일치)으로 출력을 다시 만들고, BM3D·DnCNN-S는 float 출력을 8비트로 반올림한다. 모든 출력은 같은 시드 0 잡음에서 다시 만들며, 사진별 PSNR이 저장값(`int_eval.json` 10⁻⁵ dB, `baselines.json`·`bm3d_protocol.json`·`dncnn_s_protocol.json` 10⁻³ dB)과 맞지 않으면 멈춘다. 정수 모델의 최대 차이는 1.5×10⁻⁶ dB였다. 출력 영상은 픽셀까지 같고, 차이는 `common.psnr`이 float32로 평균을 내는데 int_eval.json을 만든 PC의 numpy가 그 합을 다르게 반올림한 데서 온다(확인: `dn_d10_c45_us_fx_qat`의 Set12 12장을 양자화기의 정수 모델과 보드 드라이버로 다시 만들면 두 출력은 모든 픽셀이 같고, 둘 다 int_eval.json과 최대 4.8×10⁻⁷ dB 다르다). 처음에 적었던 '공용 `to_image` 이전 export의 반올림 경계 픽셀' 설명은 틀렸다. 같은 이유로 `run_denoise.py`의 최종 PSNR 대조도 10⁻⁶에서 10⁻⁵ dB로 넓혔다. 이 정도 차이 검사만으로는 한 픽셀의 1 LSB 차이를 다 잡지 못하므로 픽셀 일치의 증거는 아니다. 보드 쪽의 비트 일치 증거는 그대로 층별 대조다. 4코어에서 약 40분.

### 왜 이런 설계인가: 사이클 모델

창 하나의 비용은 `max(K, ⌈COUT/P⌉ × ⌈K/T⌉)` 사이클(P=16, T=4)이다. 입력 포트가 사이클당 값 하나를 받으므로 K보다 빨라질 수 없고, **COUT ≤ P·T = 64이면 출력 채널은 비용이 없다.** 보드 실측은 여기에 창당 +1, 그리고 창당 최소 COUT 사이클(코어가 출력을 사이클당 하나씩 내보냄)이 더해진다. 보정 전 모델의 오차는 0.4–1.6%(B-32 ReLU 0.38%, B 0.70%, B-32 maxout 1.37%, A 1.63%), 보정 모델은 네 망(A, B, B-32 maxout, B-32 ReLU)에서 0.003% 이내(`train_denoise.board_cycles_per_pixel_measured`).

- A의 중간 층(K=288, COUT=32)은 계산에 144 사이클이면 되는데 입력에 288이 걸린다. 곱셈기 활용률 41%.
- **B (space-to-depth):** 창 수가 1/4이 되므로 같은 사이클 예산에 채널 64, 10층 망이 들어간다. K=576, COUT=64에서 입력과 계산이 정확히 균형(망 전체 활용률 88%). 파라미터 6.4배, 곱셈 1.6배인데 사이클은 25% 적다. B 대 A의 화질 차이는 리샘플링만의 효과가 아니라 더 큰 망의 효과다.
- **B-32 + maxout:** 채널 32(K=288)로 돌아오면 출력 64까지가 다시 공짜. 은닉층이 채널마다 후보 두 개를 내고(출력 64) PC가 재양자화할 때 큰 쪽만 넘긴다(`max(ReLU(a), ReLU(b))` = maxout). 다음 층 K는 그대로. 보드에서 이 층은 **289 사이클/창**으로 A의 출력 32 층과 같았다. 첫 층(K=36)만 출력 64개를 내보내는 64 사이클이라 픽셀당 669 → 675. 활용률 45% → 87%.
- **병목의 출처:** 입력이 사이클당 값 하나인 것은 이 설계의 선택이다. 코어의 창 입력 포트(`rtl/banked_window_mac.sv`의 `s_data[6:0]`)가 사이클당 값 하나를 받고, AXI-Stream 래퍼(`rtl/window_mac_axis.sv`)는 전송 단위(beat)당 값 4개를 그에 맞춰 1개/사이클로 풀어 넣는다. 포트를 넓히려면 래퍼만이 아니라 코어의 적재 경로도 바꿔야 한다(처음에 '래퍼의 설계'라고만 적은 것은 부정확했다). 포트를 넓혔을 때 출력 64 층(4값부터는 모든 은닉층)의 비용을 정하는 계산 항은 같은 형상의 VGG11 `features.3` 창(K=576, 출력 128, dense·sparse 창 교대) 중 계산에 묶인 창에서 이 코어(P=16, T=4)의 RTL 시뮬레이션과 창당 1 사이클 안에서 맞았다(956.2 대 956.8, `scripts/cifar_budget.py --validate`). 포트를 4-wide로 넓히면 K=288·COUT=64 층은 연산 바운드(288 대 ReLU 144)가 되어 maxout은 공짜가 아니다. 공짜 출력 채널의 한계는 대략 곱셈기 수 / 입력 폭(1값 64, 2값 32, 4값 16)이다. 창을 PC가 만드는 것도 같은 역할이다. 칩 안 라인 버퍼 구조에서는 dense 모델로 은닉층이 COUT=32에서 145, 64에서 289 사이클/창이 되고, 망 전체로 A 833, B 1,209, B-32 ReLU 319, B-32 maxout 615 사이클/px가 되어 maxout은 ReLU의 약 2배 비용이 되고 B는 A보다 느려진다(예측). 규칙은 이 입력 구조에 조건부다. 2값/사이클이면 A 907, B 1,247, B-32 ReLU 339, B-32 maxout 635 사이클/px로, dense 상한으로 이미 maxout은 1.87배, B는 A의 1.37배다(4값/사이클은 라인 버퍼와 같은 값). 보드에서 잰 활성값 밀도로 sparse 모드를 추정하면(뱅크 불균형 1.0–1.3) 2값에서 maxout 1.42–1.79배, B는 A의 0.75–0.86배로 아직 빠르고, 4값과 라인 버퍼에서 B가 A의 1.17–1.23배로 느려진다(`PAPER_KO.md` 표 III).
- **host의 몫:** im2col, 재양자화, maxout의 max를 합쳐 장당 0.07–0.13 s(4코어, numpy, 대부분 재양자화)로 50 MHz 코어 시간의 5–9%다(`python scripts/time_host.py`). 표의 벽시계는 JTAG 전송과 보드 쪽 검증 시간이다.
- **보드 실행 모드:** 모든 실행이 sparse 모드(`mode_seq=1`, 0인 활성값의 곱셈을 건너뜀)였다. 입력 항 K는 그대로라 입력에 묶인 층의 사이클은 dense와 같다. 같은 비트스트림의 CIFAR-10 실행에서 K=576, COUT=128 층은 sparse로 591.5 사이클/창이었다(dense COUT>64는 보드 미측정).

GPU에서 돈 것은 체크포인트 텐서의 저장 위치(`cuda:0`)로 확인했다. 이미 정한 대로 이 실행들을 시드 2·3으로 쓰며, 결과를 본 뒤 다시 돌려 바꾸지 않는다. 첫 epoch 학습 손실(GPU 대 CPU): ReLU 시드 2 0.009679 대 0.009686, 평균 결합 시드 2 0.010157 대 0.010170, maxout 시드 2 0.012506 대 0.012657(1.2% 차이; 시드 1 maxout 0.012602와도 다르다). 시드와 플래그는 `args`로 확인했다. 가중치 초기값과 패치·잡음은 시드만으로 정해지므로 장치가 달라도 같고, 다른 것은 부동소수점 연산뿐이다(아래처럼 실제 GPU 실행은 TF32였다면 정밀도도, 비결정적 cuDNN이라 연산 순서도 다르다; 확인: 다른 CPU에서 다시 돌린 시드 1 maxout의 epoch 1 학습 손실이 0.012599로 원래 0.012602와 같았고, 검증 PSNR은 연산 순서 차이로 23.896 대 23.794 dB였다). 시드 2의 epoch 1 학습 손실(CPU): ReLU 0.009686, maxout 0.012657, 평균 결합 0.010170. QAT와 양자화는 어느 PC에서든 CPU로 돈다. 평균 결합 시드 1의 QAT는 체크포인트(`dn_d10_c32_us_avg_fx.pt`)가 있는 옛 PC에서 한다.

스크립트가 하는 일:
- `train_denoise.py`: 망은 노드 그래프입니다(`node`, `unet_spec`). 각 노드는 코어 한 번(창 kh×kw, stride, dilation, COUT)이고, 입력 맵 여러 개를 이어 붙일 수 있으며, 후처리(maxout, pixel shuffle)는 PC 몫입니다. 사이클 모델과 보정 모델을 출력합니다.
- `qat_denoise.py`: 보드의 정수 연산(INT8 가중치, 7비트 활성값, 바이어스 단위, skip 스케일 접기, 재양자화 뒤 maxout, 8비트 출력)을 float 안에서 straight-through로 재현한 `FoldedQ`를 미세조정합니다. 활성값 스케일은 학습 변수(LSQ). 검증은 양자화를 켠 채로 하므로 남는 모델이 보드 모델입니다.
- `quantize_denoise.py`: 그래프를 정수로 바꾸고, 합성곱 형태와 보드가 스트리밍하는 im2col 형태가 모든 노드에서 같은지 확인한 뒤 export합니다. QAT 체크포인트는 범위 탐색 없이 학습된 스케일을 씁니다.
- `scripts/run_denoise.py`: 그래프를 순서대로 보드에서 실행합니다. 층마다 im2col을 만들어 CIFAR 때와 같은 보드 경로로 실행하고, 보드 쪽에서 정답과 비트 단위로 비교하며, 최종 PSNR이 `int_eval.json`과 다르면 멈춥니다. 512×512는 DMA 한도 때문에 창을 나눠 실행합니다.

## 실험 기록

### 잔차(잡음) 학습 — 정수에서 손해

마지막 층을 부호만 다른 두 채널 (w, b), (−w, −b)로 만들어 PC에서 ReLU(z) − ReLU(−z) = z로 잡음을 복원하는 방식(`--residual`, `dn_d7_c32_res`). float에서는 기존과 같았지만(−0.02 dB) 정수에서 0.3 dB를 잃었습니다(29.34 대 29.55). 원인은 확인하지 않았습니다.

### maxout — 7층 32채널에서는 효과가 작음

7층 × 32채널(K=288, 출력 64)에서 15 epoch 같은 조건 비교: 검증 PSNR이 12/15 epoch에서 maxout이 높았지만 마지막 5 epoch 평균 차이는 +0.02 dB(최고 epoch 기준 +0.12, 스크린 변동 약 0.4 dB 안; `screening/screen_A_*_train.json`). 10층 32채널(B-32)에서는 같은 예산의 QAT 대 QAT가 시드 1·2·3에서 +0.37 / +0.26, −0.03 / −0.02, +0.10 / +0.07 dB(평균 +0.15 / +0.10)로 시드 2에서 뒤집혀, 규칙 (c)에 따라 화질 이득은 주장하지 않습니다(조기 종료판끼리의 +0.54는 예산이 다른 비교). 64채널에서는 출력 128이 K를 넘겨 공짜가 아닙니다.

### 층별 활성값 범위 선택

맵마다 퍼센타일을 검증 영상 40장에서 따로 고릅니다(후보 11개, 공통값 뒤 맵별 보정). 예전 B 체크포인트에서 정수 손실 0.15 → 0.02 dB. 채널 간 범위 맞추기(cross-layer equalization)는 skip 가중치를 거칠게 만들어 더 나빴습니다.

### 2단계 U-Net — 같은 사이클에서 뒤짐

리샘플링이 공짜라는 성질로 깊이를 1/16 해상도에 두는 U-Net(`--arch unet`, 1,294 사이클/px, 669k 파라미터)을 30 epoch 비교: 검증 27.89 dB 대 B 28.14 dB(`screening/scr_unet_g2_train.json`). 경사 갱신이 100 대 160으로 적긴 했지만 이득의 조짐이 없어 보류했습니다.
