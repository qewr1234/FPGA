# FPGA CNN 이미지 잡음 제거기

잡음 섞인 흑백 사진을 넣으면 FPGA가 깨끗한 사진을 돌려줍니다. CIFAR 분류에 썼던 **같은 비트스트림**
(K=1152, COUT=128, P=16, T=4, 런타임 형상)을 그대로 쓰고, 망만 분류용에서 잡음 제거용으로 바꿨습니다.

## 설정

표준 설정인 DnCNN(Zhang et al., 2017)과 같습니다.

| 항목 | 내용 |
|---|---|
| 학습 사진 | Train400 (BSD 180×180 흑백 400장), 40×40 패치, 4가지 크기 × 8가지 뒤집기/회전 |
| 테스트 사진 | Set12 (12장), BSD68 (68장) |
| 잡음 | 가우시안 백색 잡음 σ=25 (0~255 기준) |

하드웨어 때문에 바꾼 것이 두 가지 있습니다. **비교 대상도 모두 이 조건에서 다시 측정했습니다.**

1. **잡음 사진을 [0,1]로 자르고 7비트로 양자화합니다.** 코어 입력 포트가 7비트 부호 없는 값이기 때문입니다. 실제 카메라도 값을 자릅니다.
2. **마지막 층이 깨끗한 사진을 직접 출력합니다.** DnCNN은 잡음을 예측해서 빼지만, 코어는 모든 출력에 ReLU를 걸기 때문에 음수가 있는 잡음은 낼 수 없습니다. 픽셀은 음수가 없습니다.

망은 7층 × 32채널이고, 파라미터는 47,018개입니다. 잡음 사진을 마지막 층에 한 채널 더 넣습니다(skip). 다만 짧은 학습에서는 skip의 효과가 측정되지 않았습니다(`screening/`).

## 결과 (평균 PSNR, 높을수록 좋음)

| 방법 | Set12 | BSD68 |
|---|---|---|
| 잡음 사진 | 20.33 dB | 20.48 dB |
| 미디언 3×3 | 25.43 dB | 24.89 dB |
| 가우시안 필터 | 26.56 dB | 26.13 dB |
| BM3D | **29.95 dB** | 28.37 dB |
| 이 망, float | 29.67 dB | 28.70 dB |
| **이 망, 정수 = 보드가 계산하는 값** | 29.55 dB | **28.56 dB** |

- 정수로 바꾼 손실: Set12 -0.12 dB, BSD68 -0.14 dB.
  - 활성값 범위를 최대값이 아니라 99.99 퍼센타일로 잡습니다.
  - 이 값은 테스트 사진이 아니라 학습 사진 40장(검증용)으로 골랐습니다. 최대값으로 잡았을 때는 손실이 -0.34 dB였습니다.
- **BM3D와 비교:** BSD68에서는 68장 중 51장에서 이기고 평균도 +0.19 dB 높습니다. Set12에서는 12장 중 4장에서만 이기고 평균 -0.40 dB입니다.
  - Set12에서 진 차이의 대부분은 09.png(Barbara, -2.18 dB)와 02.png(House, -1.15 dB)입니다.
  - 둘 다 줄무늬·벽돌 같은 반복 무늬가 많은 사진입니다. BM3D는 사진 전체에서 비슷한 조각을 찾아 함께 처리하는 방법이라 이런 사진에 특히 강합니다. 반면 우리 망이 한 픽셀을 계산할 때 보는 범위는 15×15 픽셀(3×3 합성곱 7층)뿐입니다.
- **보드 실측 (Set12 05.png, 256×256, 1장):** 7개 층 모두 보드에서 실행했고, 출력 전부가 정답(oracle)과 비트 단위로 일치했습니다(0 mismatches). PSNR은 20.23 → **29.58 dB**로, 정수 모델 값과 같습니다.

  | 층 | K | COUT | 사이클 | 사이클/창 |
  |---|---|---|---|---|
  | conv1 | 9 | 32 | 2,097,167 | 32.0 |
  | conv2~6 (각각) | 288 | 32 | 18,939,961~969 | 289.0 |
  | conv7 | 297 | 1 | 19,529,755 | 298.0 |
  | **합계** | | | **116,326,747** | 픽셀당 1,775 |

  - 50 MHz에서 사진 한 장의 코어 계산 시간은 **2.33초**입니다. 사이클 모델 예측(1,746/픽셀)보다 1.7% 많습니다.
  - 차이의 대부분은 conv1입니다. K=9처럼 짧은 창은 창당 고정 비용이 있어서, 모델은 9를 예측했지만 실측은 32였습니다. CIFAR conv1(K=27 → 32)과 같은 현상입니다.
  - 나머지 층은 창당 +1 사이클입니다.
  - 이 시간은 코어 계산 시간만입니다. JTAG으로 데이터를 올리고 내리는 시간은 들어 있지 않습니다.

비교 그림: `figures/05_dn_d7_c32.png` (원본 / 잡음 / 가우시안 / BM3D / 이 망).

## 실행 순서

```
python denoise/get_data.py                           # 사진 받기 (16 MB)
python denoise/baselines.py                          # 비교 대상 측정 (BM3D 포함 약 10분)
python denoise/train_denoise.py                      # 학습 (CPU 4코어에서 약 3시간)
python denoise/quantize_denoise.py --ckpt denoise/dn_d7_c32.pt
python scripts/run_denoise.py --emulate              # 보드 없이 전체 흐름 확인
python scripts/run_denoise.py --xsdb <xsdb.bat 경로> --images 05.png   # 보드
python denoise/make_figure.py --model dn_d7_c32 --image 05.png --board build/denoise_run
```

학습이 끝난 모델(`dn_d7_c32.pt`)과 보드용 파일(`export/dn_d7_c32/`)은 커밋되어 있습니다. 그래서 학습은 건너뛰고 바로 보드를 돌려도 됩니다.

보드 드라이버가 하는 일:
- 층마다 im2col을 만들어 CIFAR 때와 같은 보드 경로로 실행합니다.
- 512×512 사진은 DMA 한도(64 MB) 때문에 창을 나눠 여러 번 실행합니다.
- 보드 결과는 보드 쪽에서 정답(oracle)과 비트 단위로 비교합니다.
- 최종 PSNR이 `int_eval.json`과 다르면 멈춥니다.

## 실험: ReLU 하드웨어에서 잔차(잡음) 학습 — 효과 없음

DnCNN처럼 잡음을 예측하도록 만든 모델입니다(`train_denoise.py --residual`, `dn_d7_c32_res`).
- 코어가 모든 출력에 ReLU를 걸기 때문에, 마지막 층을 부호만 다른 두 채널 (w, b), (−w, −b)로 만들었습니다.
- PC에서 ReLU(z) − ReLU(−z) = z로 잡음을 복원합니다. 하드웨어 수정이 없고 사이클도 늘지 않습니다.
- 두 채널이 같은 INT8 스케일을 갖기 때문에, 이 분리 자체는 정수 오차를 더하지 않습니다(양자화 스크립트가 대칭인지 확인합니다).

학습 조건은 기존 모델과 똑같이 맞췄습니다(7층 × 32채널, 60 epoch, 같은 시드).

| | 기존 (깨끗한 사진 + skip) | 잔차 (부호 분리) | 차이 |
|---|---|---|---|
| Set12 float | 29.67 dB | 29.65 dB | −0.02 |
| Set12 정수 (보드) | **29.55 dB** | 29.34 dB | −0.20 (12장 중 0장에서 이김) |
| BSD68 정수 (보드) | **28.56 dB** | 28.44 dB | −0.12 (68장 중 7장에서 이김) |
| 양자화 손실 (Set12) | −0.12 dB | −0.30 dB | |

- float에서는 성능이 같습니다. 기존 모델의 skip 연결(잡음 사진을 마지막 층에 다시 넣기)이 잔차 학습과 같은 역할을 이미 하고 있었다는 뜻으로 보입니다.
- 정수로 바꾸면 잔차 모델이 더 많이 잃습니다. 원인은 아직 확인하지 않았습니다.
- 보드에는 기존 모델 `dn_d7_c32`를 그대로 씁니다.
